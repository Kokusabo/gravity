# Керування двигуном і розподілом навантаження за наявністю 12В

Код: [`src/main (11).cpp`](src/main%20(11).cpp).

## 1. Ідея

ESP32 стежить, чи є напруга 12В зовнішньої мережі (через оптопару) і в
якому положенні кінцевий вимикач, та відповідно керує трьома реле:
двигун, розподіл навантаження і гальмо.

## 2. Пінаут

| Сигнал | GPIO | Константа |
|---|---|---|
| Оптопара (колектор) | 33 | `PIN_OPTOCOUPLER` |
| Кінцевий вимикач | 4 | `PIN_LIMIT_SWITCH` |
| Реле 1 (двигун) | 32 | `PIN_RELAY_1_MOTOR` |
| Реле 2 (розподіл навантаження) | 27 | `PIN_RELAY_2_LOAD` |
| Реле 3 (гальмо) | 26 | `PIN_RELAY_3_BRAKE` |
| INA3221 SDA | 21 | — |
| INA3221 SCL | 22 | — |

⚠️ Піни реле (32/27/26) перенесені з попередньої версії проєкту й ще не
перевірені фізичним тестом на поточній платі. Перед підключенням
реального двигуна під напругою: тимчасово обгорни робочий код `setup()`/
`loop()` в `#if 0 ... #endif` і встав простий тест `digitalWrite(pin,
HIGH/LOW)` з `delay()` для кожного піна окремо, дивлячись, яке фізичне
реле клацає.

Гальмо: NO-контакт реле 3 замкнутий на GND. Коли котушка знеструмлена
(реле вимкнене чи взагалі втратило живлення) — контакт розімкнутий,
гальмо відпущене. Це навмисний апаратний fail-safe: якщо зникне 12В або
живлення самого реле-модуля, гальмо автоматично звільниться, а не
залишиться затиснутим.

**Датчик струму INA3221** (I2C, канал 1) підключено послідовно в
мінусовий провід мотора й прочитується напряму по I2C-регістрах (без
зовнішньої бібліотеки). Другий (поточний) модуль має піни VS/VPU
замість VCC — обидва об'єднані й підключені на 3.3V:

```
VS+VPU -> 3.3V (ESP32)   (VS - живлення чипа, VPU - підтяжка I2C)
GND    -> спільний GND
SDA    -> GPIO21
SCL    -> GPIO22
IN1-   -> "-" клема мотора
IN1+   -> спільний GND (те, куди раніше йшов мінус мотора напряму)
```

Якщо показання струму вийдуть від'ємні — поміняти місцями IN1+/IN1-.
Адреса на шині `0x40` (`INA3221_ADDR`) — стандартна за даташитом,
визначено сканером I2C при старті прошивки (попередній модуль мав
нестандартну `0x50`). При старті в консоль друкується, чи відповідає
датчик на I2C; якщо ні — в діагностичному рядку струм виводиться як
"н/д".

**Опір шунта (`INA3221_SHUNT_OHM`) — `0.1` Ом, визначено ЕМПІРИЧНО** для
цього (другого) модуля за трьома незалежними замірами (реальний струм з
ЛБЖ / показання до уточнення), усі зійшлись до ~0.1 Ом — підпис "R100"
на цьому модулі виявився правильним:

| Реальний струм | Показано | Розрахований опір |
|---|---|---|
| 536 мА | 562 мА | ≈0.1000 Ом |
| 624 мА | 655 мА | ≈0.1001 Ом |
| 700 мА | 732 мА | ≈0.0998 Ом |

Межа вимірювання каналу при такому опорі — `163.8 мВ / 0.1 Ом ≈ 1.64 А`
(значно краще за ~490 мА попереднього модуля, мало б вистачити і на
пусковий струм двигуна). Вище цієї межі АЦП шунта фізично "зрізається"
(насичення) — не помилка коду чи I2C.

Блок реле живиться **окремо**: 5В через DC-DC понижувач, який бере ті
самі 12В зовнішньої мережі. GND реле-модуля - спільний з ESP32, VCC
реле-модуля - НЕ з ESP32 (інакше просідання напруги від котушок реле
може скидати/шумити логіку ESP32).

## 3. Вимір енергії циклу підйом/опускання

Разовий вимір ефективності: з'явилось 12В → двигун піднімає вантаж
(рахується спожита енергія), 12В зникло → вантаж опускається і генерує
(рахується згенерована енергія), струм впав майже до нуля → в консоль
друкується підсумок (обидва значення в Дж + ККД циклу), і головний цикл
зупиняється назавжди (потрібен ресет плати для нового вимірювання).

```cpp
const float SYSTEM_VOLTAGE_V = 12.0;          // номінальна напруга для P=V*I
const float ENERGY_NEAR_ZERO_MA = 20.0;       // поріг "струм ≈ 0" (шум датчика)
const unsigned long ENERGY_NEAR_ZERO_CONFIRM_MS = 1000;
const unsigned long ENERGY_SAMPLE_INTERVAL_MS = 100;  // крок інтегрування
```

⚠️ Потужність рахується як `SYSTEM_VOLTAGE_V * струм`, а не за реальною
напругою на моторі — INA3221 тут міряє тільки струм (IN1+/IN1- обидва на
"мінусовій" стороні кола, не на клемах мотора). Якщо тестуєш не на
номінальних 12В (наприклад, лампочкою на 1-2В, як раніше) — постав
реальну напругу в `SYSTEM_VOLTAGE_V` перед прошивкою для точного
результату.

Поріг `ENERGY_NEAR_ZERO_MA` (20 мА) — орієнтовний; якщо консоль показує
помітний ненульовий "шумовий" струм навіть у стані повного спокою —
підніми поріг, або опусти, якщо 20 мА зрізає останню фазу згенерованого
струму зарано.

## 4. Алгоритм

**Реле 1 (двигун)** — УВІМКНЕНО, коли є напруга 12В **і** кінцевик
**розімкнутий**. В усіх інших випадках — ВИМКНЕНО.

```cpp
bool relay1ShouldBe = voltagePresent && limitOpen;
```

**Реле 2 (розподіл навантаження)** — УВІМКНЕНО, коли є напруга 12В;
ВИМКНЕНО, коли немає.

```cpp
bool relay2ShouldBe = voltagePresent;
```

**Реле 3 (гальмо)** — УВІМКНЕНО, коли є напруга 12В **і** кінцевик
**замкнутий** (вантаж доїхав до верхньої точки), але не одразу — тільки
якщо ця умова протрималась стабільною `BRAKE_ENGAGE_DELAY_MS` (300 мс).
ВИМКНЕНО — в усіх інших випадках, завжди одразу, без затримки.

```cpp
bool brakeCondition = voltagePresent && !limitOpen;   // кінцевик замкнутий
bool relay3ShouldBe = brakeCondition &&
                       (currentTime - brakeConditionSince >= BRAKE_ENGAGE_DELAY_MS);
```

Повна таблиця станів для реле 1 і реле 3 (взаємовиключні за побудовою —
одна й та сама умова `limitOpen` ніколи не дає "true" для обох одразу):

| 12В | Кінцевик | Реле 1 (двигун) | Реле 3 (гальмо) |
|---|---|---|---|
| є | розімкнутий | привід | вимкнено |
| є | замкнутий | вимкнено | увімкнено (із затримкою) |
| немає | розімкнутий | вільний хід | вимкнено |
| немає | замкнутий | вільний хід | вимкнено |

## 5. Оптопара: тільки `digitalRead`, НІКОЛИ `analogRead` на цьому піні

⚠️ **Не викликати `analogRead`/`analogReadMilliVolts` на GPIO33.**
В Arduino-ESP32 це перемикає пін в аналоговий режим і **вимикає
внутрішній pull-up**. Пін тоді "висить у повітрі": у стані "напруги
нема" він повільно сповзає до ~140 мВ і виглядає як "напруга є". Саме це
давало симптоми "digitalRead завжди LOW" і "12В є після перших
перемикань" (мВ після вимкнення 12В піднімалось до 600-700 і за секунди
падало до 142).

Тепер: `INPUT_PULLUP` + `digitalRead` (LOW = транзистор оптопари
відкритий = 12В є), голосування більшості з 8 відліків і часове
підтвердження 500 мс (`OPTO_CONFIRM_MS`). Якщо внутрішнього pull-up
виявиться замало — додати зовнішній резистор 10 кОм між GPIO33 і 3.3В.

## 6. Чому кінцевик має дебаунс

Без дебаунсу спостерігалось хаотичне перемикання реле "по колу" —
механічний контакт кінцевика "дребезжав" (можливо, від вібрації самого
двигуна під час руху), і без фільтрації кожен дребезг сприймався як
реальна зміна стану. `isLimitOpen()` вимагає стабільності протягом
`LIMIT_CONFIRM_MS` (50 мс) перед тим, як прийняти нове значення.

## 7. Захист контактів реле від дриґання

Окремо від фільтрації сигналів (п. 5-6) — фізичне перемикання кожного
реле обмежене `RELAY_MIN_SWITCH_INTERVAL` (300 мс): навіть якщо
джерело сигналу продовжує "тремтіти", контакти реле не клацають
частіше цього інтервалу.

## 8. Збірка і прошивка

```
pio run              # збірка
pio run -t upload    # прошивка
pio device monitor -b 115200   # монітор порту
```

## 9. Відкриті питання

- Піни реле (32/27/26, Реле 1/2/3) не перевірені фізичним тестом на
  поточній платі (див. п. 2).
- Активний рівень реле 1 і 2 вже перевірено емпірично — обидва
  інверсні (`LOW` = увімкнено, див. `RELAY_1_ON_LEVEL`/`RELAY_2_ON_LEVEL`).
  Реле 3 поставлено так само (`RELAY_3_ON_LEVEL = LOW`) за аналогією,
  але це ще не перевірено окремо — перевір при першому ввімкненні.
- Вимір енергії (п. 3) рахує потужність за номінальною напругою, не
  за реальною на моторі — якщо треба точніше, доведеться підключити
  окреме вимірювання напруги на клемах мотора.
