# Керування двигуном і розподілом навантаження за наявністю 12В

Код: [`src/main (11).cpp`](src/main%20(11).cpp).

## 1. Ідея

ESP32 стежить, чи є напруга 12В зовнішньої мережі (через оптопару) і в
якому положенні кінцевий вимикач, та відповідно керує двома реле.

## 2. Пінаут

| Сигнал | GPIO | Константа |
|---|---|---|
| Оптопара (колектор) | 33 | `PIN_OPTOCOUPLER` |
| Кінцевий вимикач | 4 | `PIN_LIMIT_SWITCH` |
| Реле 1 (двигун) | 32 | `PIN_RELAY_1_MOTOR` |
| Реле 2 (розподіл навантаження) | 27 | `PIN_RELAY_2_LOAD` |

⚠️ Піни реле (32/27) перенесені з попередньої версії проєкту й ще не
перевірені фізичним тестом на поточній платі. Перед підключенням
реального двигуна під напругою: тимчасово обгорни робочий код `setup()`/
`loop()` в `#if 0 ... #endif` і встав простий тест `digitalWrite(pin,
HIGH/LOW)` з `delay()` для кожного піна окремо, дивлячись, яке фізичне
реле клацає.

Блок реле живиться **окремо**: 5В через DC-DC понижувач, який бере ті
самі 12В зовнішньої мережі. GND реле-модуля - спільний з ESP32, VCC
реле-модуля - НЕ з ESP32 (інакше просідання напруги від котушок реле
може скидати/шумити логіку ESP32).

## 3. Алгоритм

**Реле 1 (двигун)** — УВІМКНЕНО, коли є напруга 12В **і** кінцевик
**розімкнутий**. В усіх інших випадках — ВИМКНЕНО.

```cpp
bool relay1ShouldBe = voltagePresent && limitOpen;
```

**Реле 2 (розподіл навантаження)** — УВІМКНЕНО, коли є напруга 12В;
ВИМКНЕНО, коли немає.

```cpp
bool relay2ShouldBe = voltagePresent;
```

## 4. Оптопара: тільки `digitalRead`, НІКОЛИ `analogRead` на цьому піні

⚠️ **Не викликати `analogRead`/`analogReadMilliVolts` на GPIO33.**
В Arduino-ESP32 це перемикає пін в аналоговий режим і **вимикає
внутрішній pull-up**. Пін тоді "висить у повітрі": у стані "напруги
нема" він повільно сповзає до ~140 мВ і виглядає як "напруга є". Саме це
давало симптоми "digitalRead завжди LOW" і "12В є після перших
перемикань" (мВ після вимкнення 12В піднімалось до 600-700 і за секунди
падало до 142).

Тепер: `INPUT_PULLUP` + `digitalRead` (LOW = транзистор оптопари
відкритий = 12В є), голосування більшості з 8 відліків і часове
підтвердження 500 мс (`OPTO_CONFIRM_MS`). Якщо внутрішнього pull-up
виявиться замало — додати зовнішній резистор 10 кОм між GPIO33 і 3.3В.

## 5. Чому кінцевик має дебаунс

Без дебаунсу спостерігалось хаотичне перемикання реле "по колу" —
механічний контакт кінцевика "дребезжав" (можливо, від вібрації самого
двигуна під час руху), і без фільтрації кожен дребезг сприймався як
реальна зміна стану. `isLimitOpen()` вимагає стабільності протягом
`LIMIT_CONFIRM_MS` (50 мс) перед тим, як прийняти нове значення.

## 6. Захист контактів реле від дриґання

Окремо від фільтрації сигналів (п. 4-5) — фізичне перемикання кожного
реле обмежене `RELAY_MIN_SWITCH_INTERVAL` (300 мс): навіть якщо
джерело сигналу продовжує "тремтіти", контакти реле не клацають
частіше цього інтервалу.

## 7. Збірка і прошивка

```
pio run              # збірка
pio run -t upload    # прошивка
pio device monitor -b 115200   # монітор порту
```

## 8. Відкриті питання

- Піни реле (32/27, Реле 1/Реле 2) не перевірені фізичним тестом на
  поточній платі (див. п. 2).
- Активний рівень реле (чи `HIGH` дійсно вмикає реле на цій платі, чи
  логіка інверсна) теж варто перевірити емпірично при першому
  ввімкненні.
